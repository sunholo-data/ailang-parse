# Benchmark Skill — Reference

## summary.json schema

Generated by `benchmarks/officedocbench/eval_officedocbench.py:_write_summary()`.

```jsonc
{
  "schema_version": 1,
  "run_date": "2026-04-07",          // UTC date string
  "total_files": 69,                  // total benchmark files
  "adapters": [                       // sorted by adjusted score, descending
    {
      "id": "ailang_parse",           // stable id used by data-bench attrs
      "name": "AILANG Parse",         // display name
      "version": "0.3.0",
      "files_ok": 69,
      "files_total": 69,
      "coverage": 1.0,                // files_ok / files_total
      "composite": 0.9393,            // weighted average of all metrics
      "adjusted": 0.9393,             // composite * coverage
      "feature_detection": 0.9191,
      "structural_recall": 0.9879,
      "structural_quality": 0.9535,
      "content_fidelity": 0.8139,
      "text_jaccard": 0.9322,
      "element_count": 0.9723,
      "metadata": 0.9964,
      "per_format": {
        "docx": { "composite": 0.9094, "files": 29 },
        "pptx": { "composite": 0.944,  "files": 8  }
      }
    }
  ]
}
```

## data-bench attribute paths

Used in `docs/*.html` and resolved by `docs/js/bench-data.js`.

### Top-level
- `data-bench="total_files"` — `69`
- `data-bench="run_date"` — `2026-04-07`

### Per-adapter
- `data-bench="<id>.composite"`
- `data-bench="<id>.adjusted"`
- `data-bench="<id>.coverage"`
- `data-bench="<id>.feature_detection"`
- `data-bench="<id>.structural_recall"`
- `data-bench="<id>.structural_quality"`
- `data-bench="<id>.content_fidelity"`
- `data-bench="<id>.text_jaccard"`
- `data-bench="<id>.element_count"`
- `data-bench="<id>.metadata"`
- `data-bench="<id>.per_format.<fmt>.composite"`
- `data-bench="<id>.per_format.<fmt>.files"`

### Modes
- Default → `textContent` (auto-formats `[0,1]` floats as percentages)
- `data-bench-attr="<name>"` → write raw 0-100 to that attribute (used for `data-width` on bar chart fills)
- `data-bench-style="<prop>"` → write percentage string to inline style (used for `style="width: X%"` bars)

The "manual" pages have the AILANG Parse composite as **literal text** in
`<script type="application/ld+json">` blocks because search engines need it
inline — they cannot evaluate JS-replaced text. The post-check script reminds
you which files to update when the composite changes.

## Why summary.json sorts by adjusted

Coverage-adjusted = composite × (files parsed / total files). It penalises
tools that skip formats. AILANG Parse is the only parser with 100% coverage,
so its composite and adjusted scores are equal. Sorting by `adjusted` puts the
most honest leaderboard order in the JSON, which the website renders top-down.
