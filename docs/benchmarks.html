What we measure

Each file is scored on eight measures. Seven compare the parser’s output with the expected answer: feature detection, structural recall, structural quality, content fidelity, text overlap, element count and metadata. Their weights are 15%, 20%, 15%, 15%, 10%, 15% and 10%.

The eighth, structural fidelity, checks specific facts taken from the original Office XML: which cell a value is in and which cells are merged, sheet and slide order, what a comment is attached to, which slide a speaker note belongs to, list depth, formatting, formulas, links, bookmarks and breaks. Where a file has these checks they are 25% of its score. The 18 files added in version 2 are scored on them alone.

A measure that doesn’t apply to a file is left out of its average. Separate tests confirm that known mistakes, such as a shifted column or a misplaced note, lower the score.

Not everything is checked yet: theme colours, number display formats, image bytes and document generation have their own tests. The test files are pinned by hash, so a changed file cannot quietly change the comparison.

Why AILANG?

AILANG Parse is written in AILANG, a language designed for building AI-native applications. The language is a large part of the reason for these results.

Same Input, Same Output

The parsing code is marked pure func, and the compiler enforces it: that code cannot read files, call the network or use randomness. The same document always gives the same output. Structural recall is 99.3%.

Typed Blocks

Every parser returns the same 9 block types: Text, Heading, Table, Image, Audio, Video, List, Section and Change. The compiler checks that every parser and every output format handles all of them, so a block type cannot be half supported. Other parsers typically return untyped dictionaries.

Zero Runtime Dependencies

Every parser is written in AILANG with only its standard library. No Python, no Java, no system libraries. Unzipping, XML parsing and format detection are all AILANG code, with tests and Z3-verified contracts. The whole parser fits in a single binary.

Contracts and Tests

Z3 verifies 50+ contracts at build time. For example, format detection can only return a known format, and converting a list of elements never adds or drops one. Tests written next to the functions (tests [...]) catch regressions early.

AI Only for PDFs and Images

Image parsing, and PDF parsing when you choose the AI backend, use an AI model that you pick (--ai gemini-3.5-flash-lite, --ai claude-haiku, --ai granite-docling). Office parsing uses no AI at all: it reads the XML directly. The benchmark scores reflect the code, not a model.

docparse/services/docx_parser.ail 
-- Extract track change annotations from a paragraph
-- Finds w:ins, w:del, w:moveTo, w:moveFrom and creates ChangeBlocks
-- with author, date, change type, and affected text.
pure func extractParagraphChanges(p: XmlNode) -> [Block] {
  let children = getChildren(p);
  flatMap(extractChangeFromNode, children)
}

-- Create a ChangeBlock from a track change XML node
pure func makeChangeBlock(changeType: string, node: XmlNode) -> Block {
  let author = getOrElse(getAttr(node, "w:author"), "Unknown");
  let date = getOrElse(getAttr(node, "w:date"), "");
  let text = extractChangeText(node);
  ChangeBlock({changeType: changeType, author: author, date: date, text: text})
}

Built Against the Tests

We don't write the parser first and measure it afterwards. The tests come first, and AI writes the parsing code to pass them. That is why the scores are high, and why we want to find documents that lower them.

01

Write the test

We write a test file with known structure, such as merged cells, track changes, speaker notes and threaded comments, and check the expected answer by hand.

02

AI writes the parser

An AI agent reads the relevant spec (ECMA-376 for Office, RFC 5322 for email) and writes AILANG parsing code to pass the test. Z3 contracts check the code.

03

Score improves

The score goes up because the code was written to pass the test. That is the point, and it is why new test cases that lower the score are so valuable.

Most parsers are written first and measured later. AILANG Parse does it the other way round. We also test for structure that many parsers do not return, such as track changes, comments and bookmarks, so the tables above show real differences in what each parser can do.

PDFs

OfficeDocBench measures our own parsing code on Office files. PDFs are different: by default AILANG Parse reads a PDF’s text without AI, and for scans you can choose an AI backend, where accuracy depends on the model you pick. We do not publish a PDF score here. How PDF parsing works.

arxivbench — LaTeX / arXiv papers

The same comparison for scientific papers: reading the source directly against running OCR on a PDF. arxivbench scores each parser on 19 peer-reviewed arXiv papers in ML, physics, math and CS. Run the Benchmarks

The OfficeDocBench numbers on this page come from benchmarks/officedocbench/results/summary.json, which is rewritten on every benchmark run. There are three ways to reproduce them, depending on what you have installed:

# 1. AILANG Parse only — instant, no extra dependencies
uv run benchmarks/officedocbench/eval_officedocbench.py

# 2. One other parser (it must be installed)
uv run benchmarks/officedocbench/eval_officedocbench.py --adapter kreuzberg

# 3. Every parser
uv pip install -e '.[competitors]'
uv run benchmarks/officedocbench/eval_officedocbench.py --all

Useful flags: --format docx limits the run to one format; --json and --latex change the report format.

The --all run writes summary.json and a copy at docs/data/officedocbench-summary.json. The OfficeDocBench scores, parser versions and run dates on this site are read from that file, not typed by hand. To add your own parser, implement OfficeDocBenchAdapter in adapters/ and register it in eval_officedocbench.py:load_adapter().

Frequently Asked Questions

How does AILANG Parse compare to other document parsers on benchmarks?

OfficeDocBench v2 runs 10 parsers on 87 files in 11 formats. AILANG Parse scores 98.1% and parses 87 of 87 files. Scores, tested versions and errors are published for every parser.

How does AILANG Parse compare with MarkItDown?

MarkItDown 0.1.5 scores 58.7% composite on the files it parses and 46.6% coverage-adjusted. It parses 69 of 87 files: ODT, ODP, ODS, Markdown and TSV are unsupported. On Word files alone it scores 42.8% against 97.1%; comments, tracked changes, speaker notes, bookmarks and section breaks are not in its output, and nested lists come back flat. See the outputs side by side.

Is the OfficeDocBench benchmark open source?

Yes. The test files, the expected answers, the scoring code, the wrapper for each parser and the per-file results are all public. Scoring combines structure checks and text comparison.

Why do parsers score differently?

Parsers return different amounts of structure and support different formats. Version 2 gives credit for structure a parser does return, such as worksheet names and speaker notes. Missing structure and failed files stay in the results.

How are the expected answers checked?

Sixty-one Office files have answers taken directly from their source XML, and the files are pinned by hash. Eight more have selected answers checked against their source HTML or XML; the rest of the version 1 answers were written by hand and have not been rechecked. Separate tests confirm that known mistakes lower the score.

How can I submit a document that doesn't parse correctly?

Email it to docparse@sunholo.com. If it shows a parsing gap and we add it to our test set, you get 1 month of Business tier free (worth €99). You can anonymize content before sending. We accept any format: Office, email, calendar or anything else. See Help Us Find Our Gaps for details.
