Review comments from Word, Excel and PowerPoint, as data. Comments hold the questions and objections raised in review, and they are lost when a file is converted to PDF or plain text. AILANG Parse returns each comment with its author, date, replies and the exact text it is attached to, so your AI application can answer “what did legal say about this clause?”

The Problem

Comments are where people discuss an Office document. They record who raised a concern, when, which text they were responding to, and the replies that followed.

Converting the file to PDF loses that review history.

Office keeps comments in their own files inside the document (word/comments.xml, xl/comments1.xml, ppt/comments/comment1.xml), with markers that link each comment to the content it is about. A parser that works from a PDF never sees those files.

How It Works

AILANG Parse reads the Office file itself, with no conversion to PDF on the way. An Office file is a ZIP archive of XML files (the OOXML format), and the comments are read from the XML files that hold them.

DOCX (Word)

Word stores comments in word/comments.xml as w:comment elements, each with an id (w:id), author (w:author) and date (w:date). In the document text (word/document.xml), w:commentRangeStart and w:commentRangeEnd markers surround the exact words the comment is attached to. AILANG Parse matches the two, so each comment comes with the text it is about.

Replies are recorded in a separate file, word/commentsExtended.xml, which links each reply to its parent comment (w15:paraIdParent) and says whether the thread is resolved (w15:done). AILANG Parse reads it, so each reply points to its parent comment and is attached to the same text.

Sometimes a file does not say clearly what a comment is attached to: the markers are missing, a range is never closed, or the ids do not match. The comment is then returned with anchored: false and no attached text. AILANG Parse does not guess, because a comment attached to the wrong clause looks just like a correct one.

PPTX (PowerPoint)

PowerPoint has two comment formats and AILANG Parse reads both. Older decks use ppt/comments/comment1.xml, with author names in ppt/commentAuthors.xml. Current PowerPoint writes ppt/comments/modernComment_*.xml, with author names in ppt/authors.xml. A parser that reads only the older format misses every comment made in a recent version of PowerPoint.

Each comment is matched to its slide using the links stored in the slide itself, not by file number, so comments land on the right slide in decks where the numbering does not line up. A PowerPoint comment is pinned to a point on the slide, not to a run of text. AILANG Parse therefore reports the slide and its opening line, and does not invent a text range.

XLSX (Excel)

In Excel each comment names its cell directly, in a ref attribute (e.g. B5). Older notes are stored in xl/comments1.xml, with the author looked up in the file's authors list. Current threaded comments are stored in xl/threadedComments/, with author names in xl/persons/ and parentId linking each reply to its parent.

Current Excel writes both for the same comment. The older copy is there for compatibility, and its author is a placeholder like tc={guid}. AILANG Parse uses the threaded version and drops the duplicate, so a two-message thread is returned as two comments, not three. Each comment also comes with the value of its cell, such as B2: 184000, not just the cell reference.

PPTX & XLSX Comments

Comments work differently in each Office format. AILANG Parse returns them in the same shape for all three.

PowerPoint Comments

A PowerPoint comment sits at a position on a slide, not on a run of text. Reviewers use them for notes such as "Move this chart to slide 3" or "Font too small for projection". AILANG Parse returns each comment with the slide it is on.

Excel Comments

Excel comments (called "Notes" in current Excel) are attached to a cell. They often explain a formula or question a specific value. AILANG Parse returns the comment text, the author and the cell reference, so you know which figure the comment is about.

Current Excel also has "Threaded Comments", stored separately in xl/threadedComments/. These also carry timestamps and replies.

Frequently Asked Questions

How do I extract comments with author names from a DOCX file?

AILANG Parse reads comments.xml and matches each comment to the text it is attached to, using the w:commentRangeStart/w:commentRangeEnd markers. Each comment is returned with its text, author, date and the commented text.

Do PDF-based document parsers preserve DOCX comments?

No. Converting to PDF either prints comments in the margin or drops them. AILANG Parse reads them from the DOCX with author, date and commented text. See the comparison page.

Can I extract both comments and track changes from the same document?

Yes. One parse returns both. Comments and tracked changes are separate kinds of block, so you can filter for either.
