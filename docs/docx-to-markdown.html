MarkItDown vs AILANG Parse for Word documents. Microsoft MarkItDown and AILANG Parse both turn Word files into Markdown for RAG, search and LLM prompts. MarkItDown returns the body text without comments or tracked changes, and flattens nested lists. AILANG Parse keeps them, along with merged table cells, headers and footers, so your model reads what the reviewers read. On the 33 Word files in the open OfficeDocBench, AILANG Parse scores 97.1% and MarkItDown 42.8%.

AILANG Parse reads the Office XML inside the .docx directly. No AI model is involved, so the same file always gives the same Markdown, it runs on a laptop with no GPU, and the document never leaves the machine.

What you get

In the Word fileIn the Markdown
Headings# to ######, at the level the document used.
Bold, italic, links**bold**, *italic* and [text](url) on the words that carried them.
Bulleted and numbered listsMarkdown lists, nested to the depth in the document.
TablesPipe tables. Merged cells are marked {colspan=N} or {merged} instead of shifting the columns.
CommentsA quote block under the paragraph: the commented words, then the author, date and comment.
Tracked changesThe current text, plus a note for each insertion, deletion or move with who made it and when. Deleted text is struck through.
Headers and footersKept once, labelled *Header:* and *Footer:*, including tables inside them.
Document propertiesThe author line at the top; the full metadata is in the JSON.
ImagesImage blocks in the JSON. Add --describe for AI-written image descriptions (opt-in).

Parsing without --convert (docparse contract.docx, or the folder command below) writes the Markdown together with a .json file. The JSON holds the same content as labelled blocks (heading, list with item levels, table with cell spans, comment, change), for pipelines that need structure rather than text. See DOCX Parsing for that output.

Run it

Install the CLI (it also sets up the AILANG runtime):

curl -fsSL https://www.sunholo.com/ailang-parse/install.sh | sh
# One file to Markdown
docparse contract.docx --convert contract.md

# A whole folder: one .md and one .json per file, compiled once
docparse ~/contracts/ --output-dir ~/contracts-md/

# Quarto Markdown instead, ready for `quarto render`
docparse contract.docx --convert contract.qmd

Point it at a folder and it converts every file in one run, which is far faster than a loop over single files. The Markdown is identical to running --convert on each file.

Over the API

The hosted API runs the same converter. POST /api/v1/convert with target=md returns the Markdown in the JSON response:

curl -s -X POST https://docparse.ailang.sunholo.com/api/v1/convert \
  -F "filepath=@contract.docx" \
  -F "target=md" \
  -F "apiKey=$DOCPARSE_API_KEY"

Or from Python (pip install ailang-parse):

from ailang_parse import DocParse

client = DocParse(api_key="dp_...")
print(client.convert_file("contract.docx", target="md").text)

Upload files up to 32 MB directly. Send larger files by URL. API keys, plan limits and the other ways to send a file are in the API reference.

Other output formats

Change the extension after --convert: .html, .qmd, .odt, or back to .docx in your own template with --reference-doc (see Document Generation). The same command converts .odt, .pptx, .xlsx, .html and .epub to Markdown too.

Most of your documents are PDFs? The same command converts them to Markdown on your machine: --pdf-backend poppler for PDFs that contain real text, --pdf-backend docling for scans. A PDF keeps less structure than a Word file, so where the .docx still exists, convert that. See PDF Parsing.

Frequently Asked Questions

How do I convert a DOCX file to Markdown?

docparse contract.docx --convert contract.md. For a whole folder, docparse ~/contracts/ --output-dir out/ writes one .md and one .json per file. Over the hosted API, POST the file to /api/v1/convert with target=md.

Does it keep comments and tracked changes?

Yes. Each comment is kept next to the words it is anchored to, with author and date. Insertions, deletions and moves are kept as marked revisions, so the Markdown shows the current text and what was changed in review.

Do I need a GPU or an AI model?

No. The .docx is read from its Office XML. The same file always gives the same Markdown, it runs offline, and nothing is sent anywhere. AI is only used if you ask for it with --describe or --summarize.

How does it compare with MarkItDown, Docling or Pandoc on Word files?

On the 33 Word files in the open OfficeDocBench v2, AILANG Parse scores 97.1%, against 56.7% for Kreuzberg, 53.5% for Pandoc, 49.1% for Docling and 42.8% for MarkItDown. The test files, scoring code and per-file results are public on the benchmarks page.

What about PDFs and scanned documents?

The same command converts PDFs, using a PDF reader on your machine: pdftotext or poppler for PDFs that contain real text, docling for scans. Where the original Word file exists, convert that instead. A PDF keeps less structure than the Word file it came from.
