What is MCP?

The Model Context Protocol (MCP) is an open standard for connecting AI assistants to external tools and data sources. Instead of hardcoding integrations, agents discover what tools are available, what parameters they accept, and how to call them — all at runtime.

AILANG Parse exposes its parsing capabilities as MCP tools that Claude, ChatGPT, and other MCP-compatible agents can discover and use. Any agent that speaks MCP can parse documents, convert between formats, and estimate costs without custom integration code.

MCP tools are auto-discovered from the /api/v1/tools endpoint. No manual configuration of tool schemas required — agents read the manifest and know what AILANG Parse can do.
Preview feature. The MCP server interface is stabilizing. Tool names and parameters may change before the 1.0 release. Pin to a specific API version in production integrations.

Quick Start

AILANG Parse's API server already speaks MCP. The tool definitions endpoint at GET /api/v1/tools returns schemas in Claude, OpenAI, and MCP formats. Point your agent at the server and it discovers available tools automatically.

Start the Server

# Start AILANG Parse as an API server
ailang serve-api --caps IO,FS,Env,AI,Net,Rand,Clock \
  --ai gemini-2.5-flash --routes-only --port 8080 docparse/

Or use the hosted version:

# Hosted endpoint (no setup required)
curl https://docparse.ailang.sunholo.com/api/v1/tools

Claude Desktop

Add AILANG Parse to Claude Desktop by editing your claude_desktop_config.json:

{
  "mcpServers": {
    "ailang-parse": {
      "url": "http://localhost:8080/api/v1/tools",
      "apiKey": "dp_your_api_key_here"
    }
  }
}

Generic MCP Client

Any MCP-compatible client can connect to AILANG Parse. Fetch tool definitions and call tools via the REST API:

# Discover available tools
curl -s http://localhost:8080/api/v1/tools | jq '.tools'

# Parse a document (example tool call)
curl -X POST http://localhost:8080/api/v1/parse \
  -H "Content-Type: application/json" \
  -d '{"filepath": "report.docx", "apiKey": "dp_your_api_key_here"}'

# Estimate cost before parsing
curl -X POST http://localhost:8080/api/v1/estimate \
  -H "Content-Type: application/json" \
  -d '{"filepath": "report.docx", "outputFormat": "blocks"}'

Available Tools

AILANG Parse exposes the following tools via MCP:

ToolDescriptionParameters
ailang_parse Parse a document file and return structured blocks (headings, tables, images, text, lists, changes). Accepts a file path or base64-encoded content. file (path or base64), format (optional, auto-detected)
ailang_convert Convert a document from one format to another. Supports all 13 input formats and 9 output formats including Quarto Markdown. input (path or base64), output_format (e.g. html, docx, pptx)
ailang_formats List all supported input and output formats with their capabilities (deterministic vs AI-required, features). None
ailang_estimate Estimate the cost and latency for parsing a document before committing to the operation. filename, size_bytes

Each tool includes full JSON Schema parameter definitions, examples, and error types. Agents receive all of this from the /api/v1/tools endpoint — no hardcoding required.

Tool Discovery

AILANG Parse follows an agent-first design philosophy. Two endpoints power automatic discovery:

Capability Manifest

The GET /api/v1/capabilities endpoint returns a machine-readable manifest describing everything AILANG Parse can do — supported formats, determinism flags, cost metadata, and rate limits.

curl -s http://localhost:8080/api/v1/capabilities | jq '.'

Agents use this to decide whether AILANG Parse can handle a task before making a tool call.

Tool Definitions

The GET /api/v1/tools endpoint returns tool schemas in three formats:

  • Claude format — input_schema with JSON Schema parameters
  • OpenAI format — function-calling compatible parameters object
  • MCP format — Model Context Protocol standard tool definitions

Agents use this to know how to call each tool, what parameters are required, and what response shapes to expect.

# Get tool definitions in MCP format
curl -s http://localhost:8080/api/v1/tools?format=mcp | jq '.tools[0]'

# Example response (abbreviated)
# {
#   "name": "ailang_parse",
#   "description": "Parse a document file into structured blocks",
#   "inputSchema": {
#     "type": "object",
#     "properties": {
#       "file": { "type": "string", "description": "File path or base64 content" },
#       "format": { "type": "string", "description": "File format (auto-detected if omitted)" }
#     },
#     "required": ["file"]
#   }
# }

With Claude Code

If you use Claude Code, you have two options for document parsing:

Option 1: MCP Server

Configure AILANG Parse as an MCP server in your Claude Code settings. Claude will discover the tools automatically and use them when you ask it to parse or convert documents.

Option 2: Claude Code Skill

Install the AILANG Parse skill directly into Claude Code. This gives Claude native access to document parsing without running a separate server. See the Claude Code integration page for installation instructions.

Which to choose? Use the MCP server if you need document parsing across multiple agents or want a shared service. Use the Claude Code skill if you only use Claude Code and want zero-config local parsing.

With Other Agents

ChatGPT

ChatGPT supports MCP via plugins. Point your MCP plugin configuration at the AILANG Parse /api/v1/tools endpoint. ChatGPT will discover the available tools and present them as actions in the conversation.

Custom Agents

Any agent framework can use AILANG Parse via the REST API directly. The /api/v1/parse and /api/v1/estimate endpoints accept standard HTTP requests — no MCP client library required.

# Python example — call AILANG Parse from any agent
import requests

# Parse a document
response = requests.post(
    "http://localhost:8080/api/v1/parse",
    json={"filepath": "report.docx", "apiKey": "dp_your_api_key_here"}
)
blocks = response.json()

LangChain / LlamaIndex

AILANG Parse works as a document loader in LangChain and LlamaIndex pipelines. Wrap the REST API in a custom loader or use the MCP tool definitions to register AILANG Parse as a tool in your agent chain.

# LangChain custom tool example
from langchain.tools import StructuredTool

ailang_parse = StructuredTool.from_function(
    func=lambda file_path: requests.post(
        "http://localhost:8080/api/v1/parse",
        json={"filepath": file_path, "apiKey": "dp_your_api_key_here"}
    ).json(),
    name="ailang_parse",
    description="Parse a document into structured blocks"
)

Frequently Asked Questions

What is the AILANG Parse MCP server?

AILANG Parse exposes its document parsing capabilities as an MCP (Model Context Protocol) server, allowing Claude, ChatGPT, and any MCP-compatible AI agent to parse documents as a tool call. The agent sends a file, AILANG Parse returns structured blocks, and the agent can reason over the document's actual structure — not a flat text dump.

How do AI agents discover AILANG Parse as a tool?

The /api/v1/tools endpoint returns machine-readable tool definitions in Claude, OpenAI, and MCP formats. An MCP-compatible agent automatically discovers the ailang_parse, ailang_convert, and ailang_formats tools. No manual configuration needed — the agent reads the tool schema and knows how to call AILANG Parse.

Which AI agents work with the AILANG Parse MCP server?

Any MCP-compatible agent works: Claude (via Claude Code or Claude Desktop), ChatGPT (via the Actions/tool-use protocol), custom LangChain agents, and LlamaIndex agent pipelines. The MCP server also works with Cursor, Windsurf, and other IDE-integrated AI tools that support MCP.

Why is structured document parsing better for AI agents than flat text extraction?

When an AI agent receives flat text, it loses the ability to reference specific table cells, identify which text was inserted versus deleted (track changes), or attribute comments to specific reviewers. AILANG Parse gives agents a typed Block ADT where each element has semantic meaning, enabling precise reasoning about document structure.
