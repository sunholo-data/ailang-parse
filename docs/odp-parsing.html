Slides as Structured Data

An .odp file is a zip archive whose content.xml describes every slide as a draw:page element, in the OpenDocument Format (ODF). Inside each slide, text, tables, lists and images sit in draw:frame elements, using ODF's text:, table: and draw: elements. These are different from PowerPoint's XML.

Parsers that run LibreOffice to convert ODP to PPTX or PDF first can lose the slide structure and the master-slide context, and they add seconds per file. AILANG Parse reads the ODF directly. Each slide (draw:page) becomes a section block with the slide's name, holding its contents as typed blocks.

ODP and PPTX files come out in the same block format, so one piece of code handles both.

Raw ODF XML vs Structured Output

Raw content.xml
<office:body>
 <office:presentation>
  <draw:page draw:name="Slide1">
   <draw:frame>
    <draw:text-box>
     <text:h text:outline-level="1">
       Q1 Roadmap
     </text:h>
    </draw:text-box>
   </draw:frame>
   <draw:frame>
    <draw:text-box>
     <text:list>
      <text:list-item>
       <text:p>Ship v0.9</text:p>
      </text:list-item>
      <text:list-item>
       <text:p>OfficeDocBench</text:p>
      </text:list-item>
     </text:list>
    </draw:text-box>
   </draw:frame>
  </draw:page>
 </office:presentation>
</office:body>

What Gets Extracted

One Section per Slide

Every draw:page becomes a section block with kind: "slide:<name>". The slide name comes from the draw:name attribute, or a generic label when there is none.

Text Frames & Headings

Text inside draw:text-box elements becomes heading and text blocks. text:h elements keep their level (1–6); text:p elements become text blocks.

Tables on Slides

A table can sit directly on a slide or inside a frame. Either way it becomes a table block with its rows, headers and merged cells, in the same format as for DOCX and PPTX.

Bullet & Numbered Lists

text:list elements become list blocks. Each text:list-item is one entry. Empty items are left out.

Images

Embedded images (draw:image) come with their path in the file (xlink:href) and file type (MIME type). Each image stays with the slide it appears on.

Metadata

Document metadata comes from meta.xml: dc:title, dc:creator, dc:date. Useful for indexing many slide decks by author or date.

Slide-by-Slide Structure

Each slide is its own section block, so your code can go through the deck slide by slide. Want only the headings? Take the blocks with type: "section" and a kind matching "slide:*", then pick out each slide's type: "heading" blocks. Want only the slides with tables? Use the same approach with a different filter.

from ailang_parse import DocParse

result = DocParse(api_key="...").parse_file("deck.odp")

for slide in result.blocks:
    if slide.type != "section":
        continue
    print("---", slide.kind, "---")
    for block in slide.blocks:
        if block.type == "heading":
            print("H" + str(block.level), block.text)
        elif block.type == "list":
            for item in block.items:
                print("  -", item)

Use Cases

Conference Talk Archives

Many academic and open-source conferences publish slide decks in ODP. Index them by speaker, search across hundreds of decks, or feed slide outlines to an LLM without losing slide boundaries.

Mixed-Office Pipelines

Organisations where some people use LibreOffice end up with mixed PPTX and ODP archives. One parser and one output format cover both. See PPTX parsing for the PowerPoint counterpart.

Slide-Level RAG

Each slide can be retrieved as one chunk. Embed the slide as a unit instead of a fixed-size piece of flattened text, so the model gets a whole slide and not half of slide 4 plus half of slide 5.

Outline Extraction

Pull every slide title for an automatic table of contents. Generate PPTX or QMD output from an ODP source for cross-tool collaboration.

Browser-Based Review

Drop an ODP into the Workbench. It is parsed in your browser tab and never leaves your device. Useful when slide decks are confidential.

Format Migration

Convert ODP archives to PPTX, HTML or Markdown. Slides, text, lists and images survive the conversion, and nothing has to be rendered.

Frequently Asked Questions

How do I parse an ODP file to JSON?

Drop it into the Workbench, send it to the API, or use the Python/JS/Go/R SDK. The parser reads the OpenDocument Presentation XML directly, with no LibreOffice install and no conversion to PPTX.

Are slides extracted individually?

Yes. Every slide (draw:page) becomes its own section block with the slide's name. The text, tables, lists and images on that slide are typed blocks inside the section.

Does ODP parsing need LibreOffice installed?

No. content.xml is read directly from the .odp file. LibreOffice (soffice) is never run, and nothing is converted to PPTX.

What slide elements are extracted?

Text frames (draw:text-box), headings (text:h), paragraphs (text:p), tables (table:table), lists (text:list), and images (draw:image). Each stays with the slide it is on.

Does ODP parsing run in the browser?

Yes. The file is parsed in your browser tab (using WebAssembly) by the same parser the CLI uses. It never leaves your device.
