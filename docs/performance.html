Batch Mode: Start Once, Parse Many

AILANG Parse has a fixed start-up cost: it compiles its 38 modules before parsing begins. In batch mode this happens once, and every file after that is parsed without it. Batch mode is the single biggest speed-up.

Batch (multiple files or folder)

# Pass multiple files
docparse *.docx *.pptx *.xlsx

# Or an entire folder
docparse ~/Documents/

# Both auto-enable batch mode

58 files in 2.5s (44ms/file)

Loop (pays start-up every time)

# Don't do this — each invocation
# recompiles all 38 modules
for f in *.docx; do
  docparse "$f"
done

58 files in ~25s (~430ms/file)

The docparse CLI turns on batch mode by itself when you pass more than one file or a folder. No extra flags needed.

Turn Off Tracing

AILANG records a detailed trace of each run when OTEL_EXPORTER_OTLP_ENDPOINT or GOOGLE_CLOUD_PROJECT is set, and that slows parsing. The docparse CLI turns tracing off by default, which makes parsing 2–5x faster.

If you call ailang run directly instead of using the docparse CLI, set the environment variable yourself:

# Direct ailang invocation with tracing disabled
AILANG_NO_TRACE=1 ailang run --batch --entry main --caps IO,FS,Env \
  --max-recursion-depth 50000 docparse/main.ail file1.docx file2.pptx

# Re-enable tracing for debugging
AILANG_NO_TRACE=0 docparse report.docx

CLI vs API Server

CLI (docparse)

Best for: batch processing folders, CI/CD pipelines, one-off conversions.

  • Start-up cost paid once per batch
  • No network round trip
  • Reads local files directly

API Server

Best for: web apps, real-time parsing, multi-user access.

  • The parser stays loaded between requests
  • No start-up cost per request
  • Sub-100ms response for most files

For a steady stream of documents, such as user uploads, the API server has no start-up cost per file. For batch jobs on local files, pass a folder to the CLI.

Single-File Start-Up

Parsing a single file with docparse report.docx takes ~400–500ms regardless of file size. That is start-up time, not parse time. The actual parse of a 5KB DOCX is <1ms.

Quick Performance Tips

  1. Always batch. Pass folders or globs: docparse ~/inbox/ or docparse *.docx *.xlsx
  2. Use the docparse CLI. It sets AILANG_NO_TRACE=1 and turns on batch mode for you.
  3. Use the API for real-time work. The parser stays loaded, so each request takes only the time to parse.
  4. Skip AI for Office files. DOCX, PPTX, XLSX and ODF files need no AI model. Images still need --ai. PDFs use --ai by default, but you can parse them locally without AI using --pdf-backend docling (~5× faster) or --pdf-backend liteparse (~40× faster). See PDF parsing.
  5. Profile if needed. Pass -cpuprofile profile.out or -memprofile mem.out to ailang run for Go pprof analysis.

Frequently Asked Questions

How fast is AILANG Parse compared to other document parsers?

In batch mode, AILANG Parse parses 58 mixed Office files (22.9MB, 11 formats) in 2.5 seconds. That is faster than Unstructured (3.5s), Pandoc (3.6s) and Docling (8.6s), and it parses every file. Those three skip 7–19 files they don't support.

Why is AILANG Parse slow on a single file?

Every run has ~400ms of start-up time before parsing begins. Batch mode pays it once: pass several files or a folder to docparse, and the time per file drops to ~44ms.

How do I enable batch mode in AILANG Parse?

The docparse CLI turns on batch mode by itself when you pass several files or a folder. Run docparse ~/Documents/ or docparse *.docx *.pptx. No flags needed.

What does AILANG_NO_TRACE do?

AILANG_NO_TRACE=1 turns off trace collection, which slows parsing when OpenTelemetry endpoints are configured. With tracing off, parsing is 2–5x faster. The docparse CLI sets it by default.
