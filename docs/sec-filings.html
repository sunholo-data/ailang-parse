The filing is the S-1 as filed on EDGAR, fetched as-is and parsed with the docparse CLI on a laptop. Everything on this page is drawn from that one JSON output: the outline, the page numbers, the risk factors and the tables. No model was called.

A filing tool lays out each page of an EDGAR filing for print. Every line is an absolutely positioned <div> of positioned <font> fragments, and there is no <p> or <h1> anywhere. A section title is just a line in a 20pt bold font. AILANG Parse rebuilds the structure from the page geometry: it groups lines into paragraphs by their spacing, finds headings by font size and weight, picks up bullets, footnotes and page numbers, and rejoins paragraphs that were split across pages.

    Outline-First Reading

    Ask a model about an S-1 by pasting the whole filing and you spend hundreds of thousands of tokens on every question. Give it the outline first and it can choose what to read. With structured blocks, an agent can work in three steps:

    1. Read the outline. All the headings, with page numbers.
    2. Pick the sections the question needs: "What does the company say about compute supply?" points to a handful of risk factors and one sub-section of MD&A.
    3. Fetch only those blocks, using the block index on each heading, and cite the page each passage came from.

    Token counts are estimates (words × 1.3), the same rule AILANG Parse's chunker uses. The full figure counts the text of every block in the JSON.

    Tables as Data

    Financial statements in a filing are laid out for print. Empty columns hold the gap where a $ or a closing parenthesis would hang, an empty first row sets column widths, and blank rows add vertical spacing.     What Still Needs AI

    Parsing is deterministic and does not read pixels. This filing has 43 images, and some of them are content rather than decoration. The eight-page letter from the founders that opens the prospectus exists only as page images. They come through as ImageBlocks in place, so you know exactly which pages need an AI pass.     Try It

    EDGAR asks automated clients to identify themselves, so send a User-Agent with a contact address. The .json file is the structured output, and the .md file is Markdown for a model to read.

    curl -sL -A "Your Name you@example.com" -o anthropicpbc-sx1.htm \
  https://www.sec.gov/Archives/edgar/data/2130357/000162828026067168/anthropicpbc-sx1.htm

docparse anthropicpbc-sx1.htm      # writes anthropicpbc-sx1.htm.json and .md
    jq -r '.document.blocks[]
  | select(.type == "heading" and .level <= 2)
  | ("  " * (.level - 1)) + .text' anthropicpbc-sx1.htm.json
    # Carry the page and the level-1 section along, keep the risk-factor titles
jq -r 'foreach .document.blocks[] as $b ({page: "", h1: ""};
    if $b.type == "section" and $b.kind == "page-break" then .page = ($b.name // "")
    elif $b.type == "heading" and $b.level == 1 then .h1 = $b.text
    else . end;
    select(.h1 == "Risk Factors" and $b.type == "heading" and $b.level == 4)
    | "p.\(.page)  \($b.text)")' anthropicpbc-sx1.htm.json
    jq -c '.document.blocks as $b
  | ($b | map(.text) | index("Consolidated Statements of Operations Data")) as $i
  | $b[$i:] | map(select(.type == "table")) | .[0].rows[1]' anthropicpbc-sx1.htm.json
# ["Revenue","$41","$386","$4,585","$1,163","$16,286"]

    Nothing here is specific to Anthropic. Any EDGAR filing laid out the same way, such as a 10-K, 10-Q, S-1 or proxy statement, parses into the same structure. Ordinary HTML pages are not affected, because this handling only applies to pages with a fixed width and height in points. See HTML parsing for the rest, and chunking to split the result for retrieval.
