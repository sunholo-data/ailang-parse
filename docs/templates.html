Two ways to use them

1. Edit in Word

Save a copy and replace the placeholders. Use the existing Heading 1/2/3 and SunholoTable styles. You can edit the header and footer too. These are ordinary .docx files, with no macros, and they are not Word .dotx templates.

2. Generate the document from Markdown

This is what the reference files are for. A reference document is a nearly empty .docx that holds only the design: page setup, header and footer, theme, fonts and styles. Pass one to --reference-doc and your Markdown becomes the body.

Generate from Markdown

docparse draft.md \
  --convert proposal.docx \
  --reference-doc sunholo-reference.docx \
  --table-style SunholoTable

Swap sunholo for holosun or ailang. proposal.md in the kit is a skeleton with the same structure as the Word files. Copy it and fill it in. You do not need Word or LibreOffice installed: AILANG Parse writes the Word file itself.

Know these before your first run:

In your MarkdownWhat happens
# headingStarts a new page, so use it for major sections only
## / ### headingSubheadings, kept with the text that follows
Line break inside a paragraphRemoved. Use separate paragraphs where the break matters
[placeholder]Can be read as a link and disappear. Use «placeholder»

Styling from a reference doc lists which parts of the document come from the template and which are written fresh.

Design

A4 portrait; 23 mm side margins; white page; Montserrat headings and body. Colours are taken from sunholo.com: vermilion #E73C17, blue-grey #314352, pale grey #F6F8FA, with action orange #BD3012 for small link text and Heading 3.

The first page has a larger logo and header, and later pages use a compact header. Table headers repeat across page breaks. The proposal opens with a Sunholo illustration, then covers the opportunity, the delivery and the commercial next steps. Your own content will usually be longer, so look at the finished pages after editing.

Montserrat Regular and Bold are in the kit under the SIL Open Font License. The fonts are not embedded in the DOCX, so install them to see the intended layout in Word, or send the PDF.

Rebuild from source

The design is plain XML you can edit. source/parts/ holds the Word XML (OOXML) for the design. source/build.ail packs those parts and the logos into the reference documents. build.sh then uses docparse and the reference documents to generate the proposals.

templates/ ├── build.sh — runs the builder, then docparse ├── proposal.md — Markdown skeleton ├── source/build.ail — AILANG, packages OOXML with std/zip ├── source/parts/*.xml — the editable design ├── assets/ — logos + Montserrat (OFL) └── output/ — the .docx and .pdf you downloaded 
bash build.sh

The build needs AILANG and AILANG Parse, with no Python. LibreOffice and Poppler are needed only for the PDF and PNG previews.

After changing the design, check it:

docparse-audit output/sunholo-proposal.docx --strict
docparse-render output/sunholo-proposal.docx --output-dir .build/render

Then look at every rendered page. A passing audit means the file is valid. It does not tell you whether the layout or the wording is right.

Frequently Asked Questions

Are these Word proposal templates free to use?

Yes. Adapt them freely, including for commercial use. Keep OFL.txt with the Montserrat fonts if you pass those on, and replace the Sunholo and AILANG logos if you send proposals as a different company.

What is the difference between the proposal file and the reference file?

The proposal .docx is a full document you edit in Word. The reference .docx is nearly empty and holds only the design: page setup, headers, footers, theme and styles. Use it with --reference-doc. Its own text is ignored and your Markdown supplies the content.

Do I need Word or LibreOffice to generate a branded document?

No. docparse writes the Word file itself, so you do not need Office installed. LibreOffice and Poppler are needed only for PDF or PNG previews.

Are these .dotx Word templates?

No. They are ordinary .docx files, with no macros, and not .dotx templates. Save a copy and edit it, or pass the matching reference file to --reference-doc.

Can I use my own company letterhead instead?

Yes. Any existing .docx works as a reference doc. Its logo, embedded fonts and page headers are copied unchanged. These templates are an example, not a requirement.

Can I put an existing PDF into one of these templates?

Yes. docparse report.pdf --pdf-backend poppler --convert report.docx --reference-doc ailang-reference.docx reads the PDF’s headings, lists, tables and pictures and puts them on the template. PDF to Word shows this with these templates.
