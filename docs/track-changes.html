Track Changes Extraction

Who changed what, and when, read straight from the Word file.

The Problem How It Works What Gets Extracted Example Output Other Parsers Try It FAQ

Tracked changes from Word, as data. A contract’s tracked changes record who changed what, and when. Parsers that work from a PDF or from plain text lose that record. AILANG Parse reads the revision marks in the DOCX and returns every insertion, deletion and move with its author and date, so a review tool or an LLM sees the negotiation and not only the final text.

The Problem

Track changes are the negotiation history of a document. In contract review, every insertion and deletion matters: who changed what, and when.

Most document parsers drop them.

Track changes in a contract can be legally significant. A parser that drops them has lost data, not just formatting.

How It Works

A DOCX file is a ZIP archive of XML files that follow the Office Open XML standard (OOXML, ECMA-376). Word stores each tracked change as a revision mark inside the document text (word/document.xml).

AILANG Parse reads these marks directly:

  • w:ins: insertions. It wraps the inserted text and carries the author (w:author) and date (w:date).
  • w:del: deletions. It wraps the deleted text, which Word keeps in the file even though it shows it struck through.
  • w:rPrChange: formatting changes (bold, italic, font size, color), with the formatting before and after.

Each mark carries the author name and an ISO 8601 timestamp, and both are returned exactly as written. AILANG Parse does not accept or reject the changes. It returns them as data, so your application decides what to do with them.

Changes in the output

AILANG Parse returns a document as a flat list of blocks. There are 9 block types: Text, Heading, Table, Image, Audio, Video, List, Section, and Change.

Each tracked change becomes a Change block, which carries:

  • type: "insertion", "deletion", or "formatChange"
  • author: the author name from the revision mark
  • date: the ISO 8601 timestamp
  • content: the text that changed

A change is a block like any other, not a note attached to a text block. It appears in the JSON and in converted output, including Quarto Markdown, where it is written as CriticMarkup.

Section settingsw:sectPrChangeAuthor, date, the section setting that changed
Paragraph formattingw:pPrChangeAuthor, date, the paragraph formatting that changed

Every change type keeps the full author name and ISO 8601 date from the file. Nothing is guessed.

Frequently Asked Questions

How do I extract track changes from a DOCX file programmatically?

AILANG Parse reads the revision marks in the DOCX (w:ins, w:del, w:moveTo/w:moveFrom) and returns each change with its author, timestamp and change type.

Do other document parsers preserve track changes from DOCX files?

The four other parsers compared on this page do not. A parser either converts the file to PDF, which removes the changes, or extracts plain text and ignores revision marks. See the comparison page for details.

Can I get track change author and date information from a DOCX?

Yes. Every change comes with its author (w:author) and date (w:date). Dates are ISO 8601 timestamps, so you can filter, sort or build an audit trail.

What does deterministic document parsing mean?

The same file always gives the same output. AILANG Parse reads the file by fixed rules and uses no machine-learning model, so nothing varies between runs.
