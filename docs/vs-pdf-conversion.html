The Round-Trip Problem

An Office file is a ZIP archive of XML. Track changes, comments, merged cells, headers, footers and speaker notes are all in that XML, each one labelled. Converting to PDF reduces this to characters placed on a page. Then an ML model has to guess the structure from where things sit on the page.

Using Alongside Other Tools

PDFs need ML, because there is no XML to read. But Office documents are not PDFs, and sending them through a PDF pipeline loses information for no reason.

In practice: use AILANG Parse for Office formats, where it reads the XML directly, and your preferred tool for PDFs, where ML is needed.

Before: everything through one ML pipeline

# Everything through a PDF-first pipeline
from unstructured.partition.auto import partition

# Converts DOCX to PDF internally,
# then runs ML on the PDF.
# Track changes, comments, merged cells: gone.
elements = partition(filename="report.docx")

After: right tool for each format

from ailang_parse import AilangParse
from unstructured.partition.pdf import partition_pdf

if filename.endswith(('.docx', '.pptx', '.xlsx')):
    # Direct XML parse, no per-page billing, full structure
    blocks = AilangParse().parse(filename)
else:
    # ML pipeline where it's actually needed
    elements = partition_pdf(filename)

Keep your PDF pipeline as it is. Add AILANG Parse for Office formats, where reading the file directly gives better results.

Frequently Asked Questions

What exactly is lost when converting DOCX to PDF before parsing?

Five kinds of data are lost: (1) track changes and revision history, (2) which table cells are merged, (3) comments and their authors, (4) heading levels, which PDF does not record, and (5) document metadata such as custom properties. AILANG Parse keeps all five by reading the Office XML directly.

Why do wrapper-based parsers have quality problems with DOCX parsing?

Most of them wrap libraries built to display a document, not to read its structure. They miss track changes, flatten merged cells and drop comments. On OfficeDocBench, the next-best alternative scores 68.5% composite (64.6% coverage-adjusted) versus AILANG Parse's 98.1% with 100% format coverage.

Is PDF parsing always worse than direct DOCX parsing?

When the source is a DOCX, reading the XML directly is better: it is more accurate, has no per-page billing, and keeps metadata that PDF conversion drops. If your source is a PDF or a scan, you need an ML-based PDF parser. AILANG Parse does both: it reads Office XML directly and uses an AI model of your choice (Gemini, Claude, Ollama) for PDFs.
